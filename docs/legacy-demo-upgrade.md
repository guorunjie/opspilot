# 旧演示记录切换到新版

这是 `v0.1.0-dev.5` 标签之后的功能，正在准备 dev.6 候选，尚不包含在公开 dev.5 安装包中。

旧 v1/v2/v3 记录默认仍使用原引擎，安装或启动不会自动迁移、执行或改变任务结论。普通复位也不切换引擎。

## 用户链路

1. 查看页面顶部的旧版记录说明，可以先完成旧任务的回读。
2. 点击“保留旧记录并开始新版演示”。主进程显示确认框，默认取消。
3. 取消保持记录不变。确认后，旧记录作为只读存档保留；待确认、待回读和已核实状态不会被改写为成功。
4. 新演示从尚未诊断开始，需要重新诊断、预览、确认、执行和回读。旧确认不会授权新任务。
5. 展开“查看旧版演示存档（只读）”，查看旧任务状态、提交次数、确认是否存在和逐项回读结果。这里只展示历史，没有继续执行按钮。
6. 重启及新版复位均保留这份旧存档。复位不是安全擦除，不要删除数据库尝试降级。

## 保存与授权边界

旧 `pharmacy-session` 的完整值和原 revision 嵌入 v4 标记的 `legacyArchive`；一个 SQLite 条件写入同时保存存档和切换标记，避免“已切换但未保存旧记录”的两次写入间隙。新异步任务另行初始化，不复制旧计划、批准或模拟目标。

主进程在弹出确认框前记录版本号，在确认后使用同一版本做条件写入；不接受渲染进程传来的授权或版本。陈旧确认、冲突格式及损坏存档被拒绝。保存确认不明时当前句柄停止操作，需重新打开核对；不能把异常当作未写入再试。旧引擎的陈旧句柄无法覆盖新标记。

这不是将未完成旧任务转成异步任务，也不是通用生产数据迁移。旧任务只读封存后不再继续操作。任意外部旧程序、手工改库、操作系统断电和所有异步初始化崩溃点的可恢复性没有在此获得完整验收。

- 故障注入覆盖标记保存前失败、保存后确认丢失；旧记录或完整嵌入存档必须保留，当前句柄拒绝继续执行。损坏存档必须在异步初始化前拒绝。
- 主进程测试覆盖取消/确认、弹窗期间命令互斥以及忽略渲染进程注入的版本和授权。
- Windows 源码 Electron 使用临时合成 SQLite 完成：取消不变、确认切换、只读存档显示、重启保持、新任务完整回读 VERIFIED 且仅提交一次、复位保留存档。已查看实际界面截图；原生对话框回答由测试控制，不代表人工操作验收。

后续 Windows 源码验收已直接观察并点击原生确认框：取消后完整快照不变；确认后三种合成旧任务（价格已确认未执行、库存已提交未回读、活动已核实）仍保持原状态。新任务在重启后重新诊断、预览和确认，独立回读为 VERIFIED 且提交一次；复位不丢旧存档。这次没有覆盖原生对话框回答，仍不是安装包、macOS 或普通用户独立验收。

另有真实 Node 子进程测试：在嵌入旧存档的标记写入成功后立即强制退出，不进行清理；父进程观察退出后重新打开同一 SQLite，核对完整旧行仍在、异步会话尚未创建，再初始化新任务，要求零提交且无继承授权。这个单一退出点不代表所有初始化中断或断电场景已覆盖。

候选安装流程包含强制升级验收项：在临时 CI 首次启动前建立合成 v3 记录（价格已确认未执行、库存已提交未回读、活动已核实），已有 Core 目录则拒绝运行，不覆盖旧数据。实际安装后的程序必须通过取消不变、完整存档保留、重启、拒绝旧确认、新任务独立回读及复位保留存档；安装验收记录要求这些结果齐全。这不等同于旧版本二进制升级或全部历史格式验收。

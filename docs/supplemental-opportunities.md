# 库存与活动离线闭环

开发源码中的附加机会不是只读卡片：每项都能预览 → 明确确认 →
模拟执行 → 独立连接器回读 → 目标验证 → 复盘，并随 Demo 一键复位。
已发布的 dev.3 安装包包含这些改动；旧 dev.2 不包含。

## 规则及范围

- `planStockout`：仅在已知可售库存为零、仓库可用库存为正整数时提出同步建议。任一库存缺失都不会当成零。Demo 使用商品 C、可售 0、合成仓库可用 12，目标为可售 12。不是自动采购或实物补货。
- `planCampaign`：只有资格明确为真、尚未报名明确为假、活动价/成本已知且达到毛利门槛，才建议报名固定活动。缺失资格或报名状态不能推断为可报名。Demo 使用商品 A、活动价 1800 分、成本 1000 分和 20% 门槛。回读验证固定 offer 的报名状态，不声称活动真实上线或已盈利。

三类演示目标相互独立。诊断依据是固定初始合成观察，不会动态同步 ERP、
真实库存或活动资格；旧价格任务不提供其他任务的授权。

## 执行与存档

新机会使用共享 LocalTaskAgent、Task、CapabilityRegistry 和整数目标 Mock
Connector。每项各自拥有 plan ID、确认、run ID 和逐项回读历史；能力入口固定，
用户输入不能替换连接器或执行任意代码。正常、响应丢失、目标不一致、首次
回读不可用四种场景均可从界面选择。只有 mock 回读一致才报告模拟 VERIFIED。

`supplemental` 中的 Task 和目标值与原价格会话一起原子保存；首次预览新机会
将 envelope 升到 v3。加载校验固定目标、场景、状态历史、读回证据和目标值。
缺少字段、降级版本标志、跨任务计划或不一致结果会拒绝加载，保留原记录。
校验检查一致性，不是对本地存档的密码学真实性认证。

保存结果未知会冻结当前实例，重开后核对实际存档，不重发。复位同时清除
三类任务和模拟目标；新的 plan ID 使旧确认失效。v1 原价格存档不静默迁移
授权，需要完成原任务并明确复位后才能使用新机会。

## 验收范围

单元测试覆盖两项各四种场景、真实 SQLite 文件关闭/重开、跨任务授权拒绝、
非法存档保留及保存完成后响应丢失。Windows 源码 Electron 界面验证确认取消、
确认接受、提交后退出/重启、只读核对、UNKNOWN 后再核对、复盘恢复和复位重跑。
原价格四种界面场景也做回归。dev.3 的 Windows/macOS 安装包已通过临时 CI
安装、12 组界面场景、重启/复位及卸载检查，见[验证记录](verification.md)。普通用户无指导体验、
生产 Connector、完整经营模型和实际收益仍需分别验收。
